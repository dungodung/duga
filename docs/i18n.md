# Internationalisation

Duga's interface strings live in `i18n/<code>.json`, one file per language,
plus `i18n/qqq.json` for message documentation. This is the JSON "banana"
shape Wikimedia's translatewiki.net expects (see SPEC.md section 13) —
starting compatible from commit one avoids a full retranslation later.

## Adding a language

1. Copy `i18n/en.json` to `i18n/<code>.json` (Wikimedia language code, not
   necessarily ISO — see SPEC.md section 13).
2. Translate every value. Leave keys and `$1`-style placeholders untouched.
3. Add the autonym to `AUTONYMS` in `app/i18n.py`. If it's missing, the raw
   code is shown instead of breaking.
4. The language now appears automatically in the interface-language switcher
   and, once M1's `language` table exists, is a candidate for a content
   overview page too — `available_languages()` reads the directory, nothing
   is hardcoded elsewhere.

`qqq.json` is never a real language: it's read by translators (and by
translatewiki.net tooling), not end users, and is excluded from
`available_languages()`.

## Marking content-language text

`<html lang>` carries the *interface* language. Anything on the page that
is in a **content** language -- a gap's label, a term's written form, an
autonym in the language picker -- gets its own `lang` attribute, or a
screen reader announces Serbian text with an English voice.

For labels this is not simply the language being browsed. Wikidata label
lookups use a fallback chain, so a request for `sr` may answer in English,
and `wd_no_label`'s label is English by construction (the gap *is* the
missing Serbian label). Detectors therefore record `label_lang` in the gap
evidence, and the template emits `lang` only when it is present -- never a
guess. See docs/architecture.md's "Reading a long list" for the details.

## Interface vs. content language

These are independent (SPEC.md section 13): someone can browse Serbian gaps
(`/sr/gaps`, once it exists) with a French interface. `app/i18n.py`'s
`resolve_interface_lang()` picks the interface language in this order:

1. `?uselang=xx` query param (also persisted to a cookie)
2. the `duga_uselang` cookie from a previous visit
3. **the content language in the URL, for this request only** — so a first
   visit to `/sr/` isn't English chrome around Serbian content
4. `Accept-Language`
5. English

Step 3 is a same-request default, not a stored preference — it never writes
the cookie, so it doesn't collapse the two into one setting.

## Which languages are translated, and how far to trust them

Ten interface languages ship: `en`, `sr`, `fr` from M0, plus `de`, `es`,
`it`, `nl`, `pl`, `ru`, `sv`.

**The seven added later are machine-drafted and have not been reviewed by
a native speaker.** Each carries that warning in its own `@metadata.note`,
and a test asserts the warning is there. This matters more than it usually
would: SPEC.md section 13's terminology policy says translators may choose
a local term rather than transliterating "queer", and the register labels
(`slur`, `reclaimed`, `outdated`) are exactly the strings where a
plausible-but-wrong choice does damage. Treat them as a starting point for
translatewiki.net, not as finished copy -- the same status docs/i18n.md
has always given the Serbian strings.

`ceb` was deliberately left out, and Cebuano has since been dropped as a
content language too (see docs/architecture.md) — so the interface and
content sets happen to match at ten each. That is a coincidence, not an
invariant: the next content language added will have English chrome until
someone translates it, which is the normal state of affairs for a
Wikimedia tool and not a reason to machine-translate into a language
nobody here can check.

Three checks run over every message file rather than trusting review:
every language has every English key, no language has extra keys, and
every `$1`-style placeholder matches English. A dropped placeholder
renders a literal "$1" to a visitor, which is the failure that actually
breaks a page.

## What M0 ships vs. later

M0 has exactly three interface languages (English, Serbian, French) as a
proof that the pipeline works end to end, not a statement about which
languages matter most. Section 17's "line up two or three native-speaker
reviewers... before it hardens" applies to the vocabulary model, not to this
scaffolding, but the Serbian strings here are still a first draft, not
reviewed copy — treat them the same way.
